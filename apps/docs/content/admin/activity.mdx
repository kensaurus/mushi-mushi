# User activity

**Route:** `/dashboard?view=users` (**Home → User activity**). The old `/activity` link
redirects there.

> **Scenario:** You want to know whether end users are actually opening sessions
> in this project, which routes they hit, and how many of them are identified
> versus anonymous — over the last 30 days.

<AdminDocHero page="activity" />

User activity is the per-app engagement view in Mushi Mushi. It reads SDK session telemetry
(session start / heartbeat / end, page views, identity) and pairs it with report
counts for the same window.

---

## What you see

| Section | Meaning |
|---------|---------|
| **Sessions (30d)** | Sessions in the window |
| **Unique devices (30d)** | Unique devices |
| **Avg page views** / **Avg session** | Page views per session and session length |
| **Daily Active Users — last 30d** | Daily active users for the window |
| **Who uses the app** (or **Sessions by sign-in**) | Identified vs anonymous traffic |
| **Open reports** | Open, Critical and High counts, each linking to the filtered bug list |
| **Top pages by views** | Routes ranked by page views |

The window is fixed at **30 days**.

---

## Data source

```
GET /v1/admin/activity?window=30
```

Requires a console JWT and the active project (`x-project-id` via `apiFetch`).
Backed by the `project_activity_summary` RPC.

If numbers are zero after a real install, confirm the SDK has `trackSessions`
enabled (default on) and that ingest is healthy under [SDK health](/admin/sdk-health).
