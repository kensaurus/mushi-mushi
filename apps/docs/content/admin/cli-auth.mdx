# CLI device auth

**Route:** `/cli-auth?code=XXXX-XXXX`

> **Scenario:** You ran `mushi login` in a terminal. The CLI opened this page
> so you can approve the device code while signed into the console.

The page is titled **Connect your CLI**. It uses the RFC 8628 device authorization
grant for the Mushi Mushi CLI:

1. CLI starts `POST /v1/cli/auth/device/start` and opens this URL with the user code.
2. Sign in to the console if needed (`ProtectedRoute` returns you here).
3. Check that the code matches what your terminal printed. **Do not paste or type this
   code into your terminal.**
4. Click **Approve CLI connection** → `POST /v1/cli/auth/device/approve`. **Deny**
   rejects the code (`POST /v1/cli/auth/device/reject`).
5. The page polls `GET /v1/cli/auth/device/status` until the CLI claims the token
   (`cli_token_claimed_at`), then shows **CLI connected!**. The terminal wizard waits up
   to 10 minutes; if it does not continue, the tab may belong to an older run, so run
   `mushi login` again.
