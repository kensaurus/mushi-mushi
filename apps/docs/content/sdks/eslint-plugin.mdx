# `eslint-plugin-mushi-mushi`

The Mushi Mushi ESLint plugin has two lint rules for bugs AI coding tools often ship: **`no-dead-handler`**
flags event handlers that do nothing (`onClick={() => {}}`, a body that only
logs) and **`no-mock-leak`** flags faker / placeholder data left in
production paths. They run wherever ESLint runs: your editor, `pnpm lint`,
and CI.

## Install

```bash
pnpm add -D eslint-plugin-mushi-mushi
```

## Turn on the two rules

```js filename="eslint.config.js"
import mushi from 'eslint-plugin-mushi-mushi'

export default [
  // …your other configs
  {
    plugins: { 'mushi-mushi': mushi },
    rules: {
      'mushi-mushi/no-dead-handler': 'error',
      'mushi-mushi/no-mock-leak': 'error',
    },
  },
]
```

For legacy `.eslintrc`:

```json
{
  "plugins": ["mushi-mushi"],
  "rules": {
    "mushi-mushi/no-dead-handler": "error",
    "mushi-mushi/no-mock-leak": "error"
  }
}
```

## The recommended preset

`mushi.configs.recommended` (and `plugin:mushi-mushi/legacy`) turns on the
two rules above plus `no-allowlist-jsx-textnode`, which catches an allowlist
comment written as JSX text (it would render on the page) and nothing else.

```js filename="eslint.config.js"
import mushi from 'eslint-plugin-mushi-mushi'

export default [mushi.configs.recommended]
```

The plugin's other 16 rules check the Mushi console's own design system
(tokens, `<Card>`, `<PageHeaderBar>`, page posture, the widget theme) and
are only in the Mushi monorepo's `internal` preset. Turn one on by name if
it fits your app.

## Rules

### `mushi-mushi/no-dead-handler`

Flags inline event handlers (`on*` props, and `onClick` / `onSubmit`-style
object keys) whose body is empty, returns `null`, holds only `console.*` calls in a
block, or throws "not implemented", including inside `useCallback`. It checks inline
functions only: a handler passed by name, such as `onSubmit={noop}`, is not
followed. Files named `*.test.*`, `*.spec.*` and `*.stories.*` are skipped.

```jsx
// ✗ caught
<button onClick={() => {}}>Submit</button>
<button onClick={() => { console.log('clicked') }}>Save</button>

// ✓ allowed
<button onClick={() => mutate()}>Submit</button>
<form onSubmit={handleSubmit}><button type="submit">Submit</button></form>

// ✓ allowed in tests + stories
<button onClick={() => {}} />        // foo.test.tsx, *.stories.tsx
```

### `mushi-mushi/no-mock-leak`

Flags mock-library imports (`@faker-js/faker`, `faker`, `msw`, and
similar), arrays of placeholder objects (`John Doe`, `Jane Doe`), and
`lorem ipsum` or `placeholder@example.com` strings in production files. It
skips files under a `__tests__`, `test`, `tests`, `spec`, `stories`,
`fixtures`, `mocks` or `__mocks__` folder, and files named `*.test.*`,
`*.spec.*`, `*.stories.*` or `*.mock.*`. The intent is to catch the
moment a developer leaves their seed data wired up in a real page.

```ts
// ✗ caught — apps/web/src/pages/Dashboard.tsx
const projects = [
  { name: 'John Doe', tasks: 12 },
  { name: 'Jane Doe', tasks: 7 },
]

// ✓ allowed — apps/web/src/__mocks__/projects.ts
export const projects = [
  { name: 'John Doe', tasks: 12 },
]
```

## In CI

Run ESLint as its own step (for example `npx eslint .`) so a PR fails when
either rule reports. To record the findings in Mushi Mushi as well, write a
JSON report (`npx eslint -f json -o mushi-eslint.json src/`) and pass it to the
[`@mushi-mushi/mcp-ci`](/sdks/mcp-ci) `gates` command as `eslint-report`. That
command does not run ESLint itself, and its `dead_handler` and `mock_leak`
gates fail when no report is given.
