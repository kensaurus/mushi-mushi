# `@mushi-mushi/mcp-ci`

Mushi's GitHub Action. It calls the same API the MCP server uses, from a
short CI job: fail a PR while bug reports sit untriaged, have an agent open
a fix PR for one report, run the pre-release gates on a commit, or refresh
the crawler's signed-in session.

## Quick start

```yaml filename=".github/workflows/mushi-gate.yml"
name: Mushi gate
on: [pull_request]
jobs:
  coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: kensaurus/mushi-mushi/packages/mcp-ci@master
        with:
          api-key:      ${{ secrets.MUSHI_API_KEY }}
          project-id:   ${{ secrets.MUSHI_PROJECT_ID }}
          command:      check-coverage
          min-coverage: '0.9'
```

`check-coverage` fails the step when fewer than `min-coverage` (default
`0.8`) of the project's reports are classified. Add a `trigger-judge` step
before it to classify waiting reports first.

## Commands

| `command:`           | What it does                                                          |
| -------------------- | --------------------------------------------------------------------- |
| `check-coverage`     | Fails when the classified share of reports is under `min-coverage`; sets the `coverage` output. |
| `trigger-judge`      | Runs classification on up to 50 unclassified reports.                 |
| `dispatch-fix`       | Queues an agent fix for `report-id` (optionally pinned with `inventory-action-node-id`). |
| `query`              | Runs a plain-English `question` against your reports and prints the answer. |
| `gates`              | Runs the gates for `commit-sha` (`all` = `dead_handler`, `mock_leak`, `api_contract`, `crawl`, `status_claim`, `orphan_endpoint`, `unknown_call`) and fails the step when one fails. |
| `discover-api`       | Walks your repo for Next.js route handlers and OpenAPI files (plus optional Supabase introspection) and sends the routes to Mushi for the `api_contract` gate. |
| `discovery-status`   | Reads what the SDK has observed; sets `ready_to_propose`, `total_events` and `route_count` outputs. |
| `propose`            | Asks the LLM proposer for an `inventory.yaml` draft and sets `proposal_id`. It does not open a PR. |
| `auth-bootstrap`     | Runs [`@mushi-mushi/inventory-auth-runner`](/sdks/inventory-auth-runner) (`npx --yes -p @mushi-mushi/inventory-auth-runner mushi-mushi-auth refresh`) to refresh the crawler's sign-in cookie. |

The action fails the step; it does not post a separate GitHub commit status.
It sends no ESLint findings, so `dead_handler` and `mock_leak` pass here: run
[`eslint-plugin-mushi-mushi`](/sdks/eslint-plugin) as its own CI step to fail
a PR on those. `crawl` is reported as skipped because the crawler runs on its
own.

## In your IDE

The same commands are exposed as MCP tools via [`@mushi-mushi/mcp`](/sdks/mcp).
Cursor, Claude Code, and Copilot can run them on your behalf when the MCP
server is configured. Inside the admin console you can also click
**Run gates** / **Run crawler** directly on each row of the User stories
page — see [Admin → User stories · Inventory](/admin/inventory).

## Inputs

| Input         | Required | Default       | Description                                          |
| ------------- | :------: | ------------- | ---------------------------------------------------- |
| `api-key`     | ✓        | —             | Project API key (`mushi_…`). Store it as a repo secret. |
| `project-id`  | ✓        | —             | Project UUID.                                        |
| `command`     | ✓        | —             | One of the commands listed above.                    |
| `api-endpoint` |         | Mushi Cloud   | Override for self-hosted Mushi deployments.          |
| `report-id`   | for `dispatch-fix` | —   | Report UUID.                                         |
| `inventory-action-node-id` |  | —     | For `dispatch-fix`: the inventory action to pin the fix to. |
| `question`    | for `query` | —          | The question to ask.                                 |
| `min-coverage` |         | `0.8`         | For `check-coverage`: the share of reports that must be classified. |
| `fail-on-quota` |        | `true`        | Set `false` to warn instead of failing on `QUOTA_EXCEEDED`. |
| `commit-sha`  |          | `GITHUB_SHA`  | For `gates`: the commit to check.                    |
| `pr-number`   |          | —             | For `gates`: the PR the findings belong to.          |
| `gates`       |          | `all`         | For `gates`: a comma-separated subset.               |
| `repo-root`   |          | the workspace | For `discover-api`: where to look for routes.        |
| `openapi-file` |         | `openapi.yaml` in `repo-root` | For `discover-api`: an explicit OpenAPI file. |
| `supabase-url`, `supabase-anon-key` | | — | For `discover-api`: optional Supabase introspection. |

The full input and output list, with more workflow examples, is in the
[package README](https://www.npmjs.com/package/@mushi-mushi/mcp-ci).
