## Why things are stuck

They are ordered by how many apps each one blocks. Fix the cause, not the single PR: most stuck PRs come down to one of these.

### 1. Self-hosted CI is the bottleneck (all apps)

A fix PR merges only after its own CI is green, and then it has to ride a release train. Each repo gets one train every 6 hours, or sooner once 15 PRs are ready.

On glot and tsumagoi, a single labelled runner serves about 20 queued runs. Every PR also runs "Compare @mushi-mushi/* to npm latest", which stays red until that repo's SDK upgrade lands.

**Do:**

- Merge the SDK upgrades:
  - glot #585;
  - tsumagoi #968;
  - solo-boss-cloud_backend #551, a Dependabot PR waiting to be recreated (requested 10-29).
- Ask the owner about labelling the idle runners.
- Cancel queued runs for heads a PR no longer has (`gh run cancel`). Two were cancelled on 10-29.

### 2. 142 fix PRs are on an Opus "hold" (needs a person)

The Opus 5.5 review puts a PR on hold when it changes behaviour, reaches outside the bug, or the fix looks wrong. A held PR never merges by itself, and nothing retries the PR.

Largest piles:

- glot: 40;
- solo-boss: 25;
- mushi-mushi: 22;
- Help Her Take Photo: 20 of 43 open;
- the-wanting-mind: 19 of 37 open.

**Do:** for each app, open `/fixes` and read each held PR's review. Then either:

- close it, and close or re-dispatch the report; or
- override the hold in the console with a written reason. Only a console session can override; API keys can't.

Spend-down retries a report 12 hours after a hold, up to 3 attempts, and puts the earlier findings in the prompt.

### 3. Local lanes lose work at commit and push

In the last 7 days, these `mushi work` runs failed:

- about 45 because the repo's own git hook rejected the agent's commit or push;
- 25 because they timed out without a change;
- 22 because they were reaped (no result came back within the lease).

Hook failures by repo:

- **yen-yen (about 30):** the pre-push `lint` step fails (`ELIFECYCLE`) in the worker's clone. The log also shows "no lint configured for shared/db-types yet".
- **glot.it (5):** the `readme-counts` pre-commit step fails because the README's migration count has drifted.
- **solo-boss-cloud (4):** the `public-shell-isolation` baseline ("public root missing force-light") rejects the commit.
- **mushi-mushi (7):** the admin raw-hex-colour check, and a `getPackageJSONURL` crash inside a hook.

**Do:** fix each hook so it passes in a fresh worker clone: either install dependencies first, or give lockfile-only and test-only commits a cheap path. This is backlog row BL-171. Never bypass a hook with `--no-verify`.

When CI fails on a PR's own commit, the merge queue blocks it. Review follow-ups then get up to 2 rounds per PR, run by cloud agents or by local lanes in `followups` mode. Many blocked rows now read "both follow-up rounds are used. Fix it on GitHub".

## How to work here without breaking things

### The owner's standing rules

- **Release in batches.** One release branch, run the PR workflow's gates locally, push once, open one PR, merge once and deploy once. Docs-only changes wait for the next batch.
- **Git:** never use `--no-verify` and never force-push. Never add Co-Authored-By or "Generated with" lines to commits or PRs.
- **Production data:** ask before any `UPDATE` or `DELETE` on production rows. Schema changes the owner asked for may be deployed without asking again.
- **Memory:** run at most 3 heavy runs at once (`tsc -b`, a full test suite, a vite build, e2e), and only with at least 4 GB free.
  - The WSL VM holds about 16 GB for the worker and runners. Don't stop it, and never run `wsl --shutdown`.
- **Browsers:** use stored profiles only, headed. Never close the `owner-console` session (profile `github-kensaurus`).
  - Never type passwords. The owner signs in with `! bash /c/Users/kensa/.playwright-cli-profiles/mushi-console-login.sh`.
- **Public copy** says "Mushi Mushi", never "Mushi".

### Repo traps

- **Deploying edge functions:** deploy only from a clean worktree that is up to date with master. A merge to master redeploys every function from master.
- **`api` size:** `api` is at its budget of 4,540,000 bytes (`scripts/deploy-edge-function.test.mjs`). Comments don't count toward it; code does.
- **Local Deno 2.9:** run `DENO_NO_PACKAGE_JSON=1 deno check …`, then `git checkout -- deno.lock`. It can write a stray `workspaces` field into `package.json`.
- **Migrations applied through the Supabase MCP** are recorded under their apply time, while the repo file keeps its own version; they're matched by name. Sync the Helm mirror with `node scripts/sync-helm-migrations.mjs`.
- **The admin design-token hook** reads text like `#880` in test files as a hex colour.
- **SDK upgrade PRs:** regenerate the lockfile with the package manager major version that wrote it:
  - npm 10: glot, cooler-heads, the-wanting-mind;
  - npm 11: solo-boss, Help Her Take Photo, tsumagoi;
  - pnpm 9: yen-yen.

## Re-run the numbers

Read-only SQL, for the Supabase SQL editor or MCP:

```sql
-- per-app backlog
with p as (select id, name from projects
           where organization_id = '5de684b4-f64a-49e4-9973-4756ecbe5809')
select p.name,
  (select count(*) from reports r where r.project_id = p.id
     and r.status in ('new','classified','reopened','fixing')) as open_reports,
  (select count(*) from fix_attempts fa where fa.project_id = p.id
     and fa.pr_url is not null and fa.merged_at is null
     and coalesce(fa.pr_state,'open') in ('open','draft')) as open_fix_prs,
  (select count(*) from fix_merge_queue q where q.project_id = p.id
     and q.state = 'blocked') as queue_blocked,
  (select count(*) from fix_attempts fa where fa.project_id = p.id
     and fa.merged_at > now() - interval '7 days') as merged_7d
from p order by open_reports desc;

-- step 6: a new local-lane failure should carry a category
select failure_category, left(error, 60), completed_at
from fix_attempts
where agent = 'mcp' and status = 'failed'
  and completed_at > '2026-10-29 09:15'
order by completed_at desc limit 10;

-- why the merge queue is blocked, per app
select p.name, left(q.detail, 120), count(*)
from fix_merge_queue q join projects p on p.id = q.project_id
where q.state = 'blocked' group by 1, 2 order by 1, 3 desc;
```
