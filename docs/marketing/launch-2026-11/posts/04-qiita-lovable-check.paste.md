Lovable / Bolt で作ったアプリの「誰も報告しない壊れ方」を無料で洗い出す

AI で作ったアプリは、公開した瞬間から「気づかれない不具合」を抱えがちです。困ったユーザーは報告より先に離脱します。私が運用している 9 本のアプリでは、2026年11月11日までの 60 日間に、ユーザーからの報告は 34 件（私自身のテストを含む）でした。一方、自動チェックや私が手動で登録したものなど、ほかの経路から届いた報告は 2,031 件ありました。

この記事では、公開中のアプリを自分で点検する手順と、それを無料で一括で行う方法をまとめます。

## 手で点検する 5 項目

### 1. ページタイトルがテンプレートのままになっていないか

Lovable や Vite のテンプレートは、`index.html` の `<title>` が「Lovable App」や「Vite + React」になっています。検索結果やブラウザのタブにそのまま出ます。

```bash
curl -s https://your-app.example.com | grep -o '<title>[^<]*</title>'
```

### 2. リンク切れがないか

フッターの「利用規約」「お問い合わせ」が、生成されたまま存在しないページを指していることがよくあります。トップページのリンクの HTTP ステータスを確認します。

```bash
curl -s https://your-app.example.com \
  | grep -oE 'href="/[^"#]*"' | sort -u | cut -d'"' -f2 \
  | while read p; do printf '%s %s\n' "$(curl -s -o /dev/null -w '%{http_code}' "https://your-app.example.com$p")" "$p"; done
```

SPA では、存在しないパスでも 200 が返ることがあります。その場合は、ブラウザで開いて中身を見てください。

### 3. 開いたときにコンソールエラーが出ていないか

DevTools の Console を開いて再読み込みします。赤いエラーが出ていれば、どこかの機能が動いていない可能性が高いです。

### 4. 表示されない画像がないか

DevTools の Network タブで「Img」に絞り、404 のものがないか確認します。

### 5. フォームが最後まで送れるか

お問い合わせや登録フォームを、本番で一度送ってみます。CAPTCHA が読み込まれない、送信ボタンが反応しない、といった不具合は報告されにくい代表例です。

## 無料で一括チェックする

上の 1〜4 をまとめて調べるのが、私が作っているオープンソースの Mushi Mushi の無料 Production Check です。URL を貼るだけで、登録は要りません。

https://kensaur.us/mushi-mushi/docs/check?src=qiita.lovable-check

訪問者に見える問題（リンク切れ、表示されない画像、開けないページ、テンプレートのままのタイトル、読み込み時のエラー）から順に表示し、セキュリティヘッダーは最後にまとめます。サイトにアクセスできなかった場合は失敗として表示され、「問題なし」の扱いにはなりません。公開ページだけを読み、ログインが必要な画面には入りません。

## 5 番目のためにできること

フォームの不具合のように、実際に使った人にしか分からない問題もあります。その人がひと言で知らせられるよう、報告ボタンを置いておくと安心です。Lovable や Bolt なら、チャットへのプロンプト 1 つで入ります（手順: https://kensaur.us/mushi-mushi/docs/quickstart/lovable-bolt?src=qiita.lovable-check ）。

届いた報告ごとに、原因の説明と、Lovable にそのまま貼れる修正プロンプトが付きます。無料プランはアプリ 1 本・月 100 件の診断までです（カード登録不要）。ボタンはブラウザの言語に合わせて日本語でも表示されます。診断と管理画面は英語です。

日本語の概要はこちらにまとめています。

https://kensaur.us/mushi-mushi/docs/ja?src=qiita.lovable-check
