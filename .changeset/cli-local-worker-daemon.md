Add `mushi work --daemon`: a local worker that fixes reports with the Cursor CLI on your machine while the console steers it (Pipeline → Workers). Every minute it sends a heartbeat, reads each lane's model, mode, concurrency, pause, drain and stop date from Mushi, checks the machine's guards (free memory, the GitHub API quota, the Cursor sign-in, one agent cap), and claims reports through a server lease, so no cloud agent works on the same report. A failure of the machine is reported apart from a failure of the code and never counts against the report. Add `mushi worker install` (writes the lanes file, imports lane-v4's `lanes.conf`, stores a `worker:run` key and writes a systemd user unit or a Windows scheduled task, after showing all of it), `mushi worker status` and `mushi worker revoke`. `mushi work` now closes a run that failed on the machine with `mushi work infra:`, which starts no 7-day cooldown. `mushi reports file --lane <id>` also puts the filed report at the end of one of your lanes.
